# ADR-0058 — Canonical Processor-Cooler BuildKit-to-Four-Point-Retention Assembly Handoff

**Status:** Accepted for source/domain/scene/input/full-regression, exact-head macOS/Windows native and technical-CI gates; source/docs CI, final canonical/local package, real-human session, healthy physical USB and administrative closure pending  
**Date:** 26 August 2026  
**Scope:** Issue #97, child of Epic #10

## Context

Issues #68 through #87 stage the exact ten reserved custom-PC components in component-specific capacity-one BuildKit slots. Issue #89 moves the same motherboard into the existing chassis Assembly authority and secures it; #91 retains the exact CPU; #93 retains the exact DDR5 UDIMM in A2; #95 secures the exact M.2 2280 NVMe in the primary slot. The original ten staging receipts remain immutable preparation history while current custody advances through Assembly.

Issue #58 already owns the single LGA1700 top-down air cooler family, ProcessorCoolerSlot/bracket topology, two keyed 180-degree orientations, support/RAM/obstruction clearance, pre-applied single-use TIM, four-point `1→3→2→4` retain and `4→2→3→1` unretain order, retained-removal block, detach and replay semantics. Issue #77 stages the reserved canonical cooler in its BuildKit slot. The missing boundary is a reservation-safe bridge from that exact BuildKit custody to the existing Issue #58 authority after the live motherboard/CPU/DDR5/M.2 prerequisite chain is proven.

A second Inventory, shadow cooler slot, regenerated cooler identity, refillable TIM shortcut or duplicate retention state would split authority. A merely visual clearance exemption would also be invalid: the native geometry must prove both supported cooler orientations are physically disjoint from the already secured M.2.

## Decision

- Resolve only the exact owned work order's canonical `ProcessorCooler` line and full `LineId`, `ProductId`, serialized `ItemId`, `ReservationId`, parent allocation and original staging-receipt tuple. Ordinal, display-name, component-only and value-equivalent matches cannot acquire authority.
- Require the historical exact ten-receipt `10/10` aggregate plus live exact Issue #89/#91/#93/#95 receipts. The motherboard must be Workbench-owned and `SeatedSecured`; CPU ProcessorSocket-owned and `ProcessorRetained`; DDR5 exact A2 MemorySlot-owned and `MemoryModuleRetained`; M.2 exact primary-slot-owned and captive-screw secured.
- Require the configured ProcessorCoolerSlot to be managed, capacity one, compatible, foreign-container-free and `EmptyOpen`. Full hands, occupied slot, stale authority/revision, wrong prerequisite or overflow fail closed.
- Use a stable cooler assembly-handoff operation identity distinct from staging, prior component handoffs and Issue #58 seat/retention operations. Immediate and delayed replay return the same immutable receipt without a second custody or revision change.
- Add only the narrowly registered ProcessorCooler BuildKit → `ActorHands` release. Subsequent reversible transfer remains the existing exact ProcessorCoolerSlot ↔ `ActorHands` Assembly path; generic reserved transfer, checkout and world drop remain closed.
- Preserve reservation and parent allocation through pickup, first seat, TIM consumption, four-point retain/unretain and detach. Preserve all ten staging receipts and visible `10/10` history while tracking current custody separately. The other five uninstalled BuildKit components and the installed motherboard/CPU/DDR5/M.2 states remain unchanged.
- Reuse Issue #58 compatibility, two-orientation guided seat, preview-equals-commit, clearance, TIM, retention and replay rules. This handoff authorizes that authority; it does not recreate or relax it.
- Commit authoritative custody before changing parent/pose/physics/visibility. If projection fails, recover the same Unity component and stable ItemId to the authoritative hands/slot pose; duplicate, ghost and loss counts remain zero.
- Consume pre-applied TIM exactly once on the first successful seat. After unretain and detach, a fresh-TIM-free reseat must atomically return `ProcessorCoolerTimConsumed`, leave the same cooler in hands and mutate no Inventory, Assembly, reservation or projection state.
- Keep retained removal blocked. Keep motherboard unsecure/detach, CPU retention opening and DDR5/M.2 custody/state changes blocked while the cooler is seated or retained.
- Keep BuildKit pickup, guided seat, retention and generic drop edges single-consumer across keyboard/mouse and gamepad. Range, focus, line of sight, pause/focus neutralization, release/repress and held/co-edge rules remain fail closed.
- Fix physical clearance in authored geometry, not in the obstruction solver: the primary M.2 slot is raised to the verified motherboard plane and the temporary M.2/cooler collision exemption is removed. Both 0° and 180° cooler seats must pass actual collider separation.
- Bind acceptance to exact technical commit/tree, full test XML, macOS and Windows native artifacts, binary/procedure hashes, graceful cleanup and package readback. Runtime acceptance requires one r49 readiness marker with `processor-cooler-assembly-handoff=ready`, one exact success marker, zero handoff-failure/fatal markers and zero player/Unity/task residue.

## Consequences

The BuildKit reports `SOĞUTUCU MONTAJDA` while its immutable `10/10` history remains visible.
